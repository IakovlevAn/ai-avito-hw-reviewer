# Avito AI Reviewer

Сайт для предварительной проверки домашних заданий Авито Образования. Первая версия работает с Go-работами, которые студенты сдают через GitHub.

## Текущий статус

Первый рабочий вертикальный сценарий реализован:

- студент открывает конкретную домашнюю работу, читает полное условие и критерии, отправляет ссылку на GitHub и следит за статусом;
- координатор фильтрует поступившие работы, контролирует сроки и загрузку команды, при необходимости меняет ревьюера;
- система фиксирует версию работы и назначает свободного Go-ревьюера;
- 25 критериев проверяются по рабочей шкале на 100 баллов;
- формальные требования получают балл, уверенность и ссылки на найденные файлы;
- три качественных критерия передаются человеку без предложенного балла;
- ревьюер читает зафиксированную версию кода внутри сервиса, оставляет комментарии к строкам, меняет или подтверждает каждый результат;
- подтверждённая проверка выгружается в Excel;
- интерфейс показывает режимы координатора, ревьюера и студента.
- при включённом Go runner проект собирается и проверяется через `go vet` в ограниченном контейнере без сети;
- зависимости и результаты компиляции кэшируются отдельно для конкретной версии работы.

Интеграция с Telegram реализована как адаптер и включается после настройки чата. Модельная проверка работает в два этапа: YandexGPT Lite разбирает качественные критерии, затем более сильная модель проверяет, не завышены ли предложенные баллы. При ошибке любой модели сохраняется детерминированный результат, а сомнительные критерии остаются ревьюеру.

Калибровка итоговой шкалы ещё продолжается. Первые прогоны показали, что общая сумма смешивает полноту выполнения и качество кода, поэтому до ручного эталона её нельзя считать окончательной оценкой уровня работы.

## Быстрый запуск

### Docker

```bash
docker compose up --build
```

Если порт 8000 занят:

```bash
APP_PORT=8001 docker compose up --build
```

После запуска сайт доступен по адресу `http://localhost:8000` или на выбранном порту.

### Разработка

```bash
make install
make dev-api
```

В отдельном терминале:

```bash
make dev-web
```

Frontend будет доступен на `http://localhost:5173`, API — на `http://localhost:8000`.

## Проверка

```bash
make test
```

Команда запускает backend-тесты и production-сборку сайта.

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните только нужные значения:

- `DATABASE_URL` — SQLite по умолчанию, можно заменить на PostgreSQL;
- `GITHUB_TOKEN` — необязателен для публичных репозиториев;
- `TELEGRAM_BOT_TOKEN` и `TELEGRAM_DEFAULT_CHAT_ID` — включают уведомления;
- `YANDEX_GPT_ENABLED`, `YANDEX_GPT_FOLDER_ID`, `YANDEX_GPT_MODEL` и `YANDEX_GPT_CRITIC_MODEL` — включают двухэтапную модельную проверку;
- `YANDEX_CLOUD_IAM_TOKEN` — только короткоживущий токен для локального запуска; в Yandex Cloud используется metadata token сервисного аккаунта;
- `GO_RUNNER_ENABLED` — включает изолированную сборку и `go vet`; по умолчанию выключен;
- `APP_PORT` — внешний порт Docker Compose.

Секреты нельзя добавлять в репозиторий.

## API

- `POST /api/submissions` — добавить GitHub-работу;
- `GET /api/dashboard` — очередь и загрузка ревьюеров;
- `GET /api/submissions/{id}` — результат проверки;
- `GET /api/submissions/{id}/files` — файлы зафиксированной версии работы;
- `POST /api/submissions/{id}/comments` — построчный комментарий ревьюера;
- `PATCH /api/submissions/{id}/reviewer` — ручное переназначение работы;
- `PATCH /api/submissions/{id}/criteria/{criterion_id}` — решение ревьюера;
- `POST /api/submissions/{id}/approve` — подтвердить итог;
- `GET /api/submissions/{id}/export.xlsx` — скачать Excel;
- `GET /healthz` — проверка состояния.

## Принципы

- Система не выставляет окончательную оценку.
- Низкая уверенность означает отказ от балла и передачу критерия ревьюеру.
- Признаки использования генеративного ИИ не влияют на баллы автоматически.
- Любой вывод должен опираться на конкретные файлы, строки, результаты сборки или тестов.
- Персональные данные, приватный код и секреты не попадают в репозиторий и логи.
